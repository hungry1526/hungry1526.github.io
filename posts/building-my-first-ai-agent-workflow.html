Building My First AI Agent Workflow

Over the past few weeks, I've been experimenting with AI agents to automate repetitive GitHub tasks — things like creating repositories, managing pull requests, and updating documentation. What started as a curiosity quickly turned into a genuinely useful workflow.

What Is an AI Agent?

An AI agent is a system that can perceive its environment, make decisions, and take actions to achieve a goal. Unlike a simple chatbot, an agent can use tools — like a terminal, a browser, or an API — to actually get things done.

The Setup

My workflow uses an AI coding assistant paired with the gh CLI (GitHub's official command-line tool). Together they can:

  • Create and delete repositories
  • Open, review, and merge pull requests
  • Update repository metadata like descriptions and licenses
  • Push code changes automatically

A Real Example

Here's a taste of what the agent ran to create this very blog: 

gh repo create hungry1526.github.io --public
git clone https://github.com/hungry1526/hungry1526.github.io.git
# ... write index.html ...
git add . && git commit -m "Initial blog site: HJ Hang Blog"
git push -u origin main

What I Learned

The biggest insight was how much friction disappears when you stop context-switching between a browser, a terminal, and an editor. Describing intent in plain English and watching the agent execute it end-to-end is a genuinely different way of working.

There's still plenty the agent gets wrong — and knowing when to intervene is a skill in itself — but for well-defined tasks like repository management, it's already a productivity multiplier.

What's Next

I'm planning to extend this workflow to handle issue triage, automated changelog generation, and deployment pipelines. Stay tuned.
